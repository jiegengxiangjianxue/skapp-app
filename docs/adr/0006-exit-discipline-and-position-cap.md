# ADR-0006：补上「卖出侧」——退出纪律引擎与仓位上限闸门

- **状态**：Accepted
- **日期**：2026-10-28
- **相关**：`engine-algo/.../ExitPlan.kt`、`PositionCap.kt`、`engine-runtime/.../LocalScreener.kt`（破位一票否决）、`EngineFeedLive.kt`、`docs/adr/0001`、`docs/adr/0004`

## 背景

端上 12 引擎 / 29 因子 / 9 相位，回答的全是**买什么**。没有任何一处回答「什么时候走」：

- 破位了，评分还在高位（下跌惯性本身会推高动量类因子），于是「高分破位票」被推荐；
- 仓位上限是 `0.8 × (相位分+100)/200` 一条直线，没有「停手」档，也不看情绪趋势；
- 界面只能给出「涨跌幅」，无法区分「跌 1% 但收在区间上沿」与「跌 1% 全是实体阴线贴着最低收」。

真实亏损主要发生在「该走没走」和「烂行情还在做」这两件事上，而不是「没买到最强的票」。

## 决策

1. **新增 `ExitPlan`（纯函数，机械规则）**：破位清仓（收盘 < 近 20 日最低且**不含今日**）、回吐波幅过半减仓、长下影只给「止跌观察」。阈值写成常量，不做可调开关——可调就会被亏损时的自己调松。
2. **新增 `PositionCap`**：把仓位上限从「相位直线」换成「硬闸门 + 三因子加权」。闸门三条：宽度 <35% 且跌停 ≥ 涨停；连板高度掉 ≥2 档且晋级率 <30%；相位 ≤-60。命中即把上限压到 20%。理由逐条带数值输出，界面标黄。
3. **破位成为推荐侧的硬规则**：`LocalScreener` 里已有候选池日 K，顺手算 `ExitPlan`，`ACT_CLEAR` 直接 `buyable = false`，并在 `reason` 写明破位原因。零额外请求。
4. **板块结构判定**：`LocalSectors` 增加 `closePos`（成员收盘在区间位置的平均）/`longShadowN`/`stopping`（止跌雏形、修复中、中性、单边下杀）。用「结构」而不是「涨跌幅」描述板块状态，对应「PCB 压根没有止跌的意思」这类判断。
5. **数据前提补齐**：`LiveMarket.Row` 取 `f16 最低`/`f17 今开`（同一次 clist 批量，零额外请求）；日级存档升到 **v3**，逐版只追加列，v1/v2 文件继续可读，缺列一律 `null` 不填收盘价。

## 后果

**正面**

- 「买点旁边放着卖点」：推股卡/详情页同时给清仓线、止盈线、今日处置动作。
- 烂行情能被明确表达为「轻仓/空仓 + 为什么」，而不是一个 0.35 的数字。
- 破位票不再进推荐，减少「追高被套」这一类最贵的错误。

**负面 / 已知取舍**

- 「回吐一半」在无持仓成本时用「区间最低收盘」代理起涨点，口径必须在界面写清（详情页已写）；真利润口径需要成本价，当前版本没有持仓模型。
- 波幅 <5% 的横盘票不启用回吐规则（否则止盈线贴着头顶，天天报警，规则会被当噪音关掉）。
- 板块结构依赖当根 `high/low`：缺失时 `stopping` 为 `null`，界面显示「不可得」，不猜。
- 仓位闸门的阈值是经验值（35%/2 档/30%/-60），未做样本外回测，需随实盘数据校准；校准前不得据此加杠杆。
